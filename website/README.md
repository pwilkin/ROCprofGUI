# rocprof studio documentation site

A **self-contained** VitePress site for rocprof-studio. It has its own `package.json` and does **not** touch the application's `package.json` / `Cargo.toml`. It is additive documentation — building or deploying it never changes the app.

```
website/
├── package.json                 # VitePress only; independent of the app
├── README.md                    # this file
├── scripts/
│   └── capture-screenshots.mjs  # re-runnable screenshot capture (Playwright)
└── docs/
    ├── .vitepress/config.mts    # nav, sidebar, and the base-path setting
    ├── index.md                 # Home
    ├── installation.md  running.md  input-formats.md
    ├── ui-tour.md  views.md  projects.md  export.md
    ├── mcp.md  kernel-tuning.md  shader-tuning.md  radv.md
    ├── limits.md  architecture.md  validation.md  troubleshooting.md
    └── public/img/              # all screenshots (served at <base>/img/…)
```

## Local preview

```bash
cd website
npm install
npm run dev          # http://localhost:5173/rocprofgui/
```

## Build

```bash
cd website
npm run build        # → docs/.vitepress/dist
npm run preview      # serve the built site locally
```

## The base path (the one setting to get right)

The site is served from `https://<owner>.github.io/<repo>/`, so the base must be `/<repo>/`. It is set in `docs/.vitepress/config.mts` and **defaults to `/rocprofgui/`** (the repository name). Override it at build time with `DOCS_BASE`:

```bash
DOCS_BASE=/my-repo/ npm run build   # a differently-named repo
DOCS_BASE=/        npm run build    # user/org root (owner.github.io) or a custom domain
```

**If your repository is not named `rocprofgui`, set `DOCS_BASE` (or edit the default in `config.mts`) — this is the only change a human must make.** The Pages workflow passes `DOCS_BASE` through from a single env value.

## Deploy to GitHub Pages

A workflow is provided at **`.github/workflows/pages.yml`** (in the repo root). It builds the site and deploys it with the official Pages actions on every push to `main` that touches `website/`, and can be run manually.

**A human must enable Pages once:** in the repository, go to **Settings → Pages → Build and deployment → Source: GitHub Actions**. Until that is done, the deploy step has nothing to publish to.

## Regenerating screenshots

Most screenshots are captured headlessly from the app's **browser preview** (the synthetic example), plus a few driven with a Tauri IPC stub (MCP control surface, kernel-tuning window). From the **repository root**:

```bash
node website/scripts/capture-screenshots.mjs           # default port 1526
node website/scripts/capture-screenshots.mjs --port 1600
```

It starts its own Vite dev server, writes PNGs into `website/docs/public/img/`, and tears the server down. It needs the repo's `node_modules` (Playwright) and an installed Playwright Chromium (`~/.cache/ms-playwright`, or set `PLAYWRIGHT_CHROMIUM_EXECUTABLE`).

Existing real desktop screenshots from `../docs/*.png` were **copied once** into `docs/public/img/`; they are not re-generated by the script. See the screenshot captions for which images are synthetic vs real captures.
